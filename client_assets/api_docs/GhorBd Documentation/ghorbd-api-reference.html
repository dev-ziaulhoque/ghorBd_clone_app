Authentication

Stateless JWT. Login and verification return accessToken (15 minutes) and refreshToken (30 days) in the JSON body. Keep both in secure storage: Keychain on iOS, EncryptedSharedPreferences or Keystore on Android.

Sign up: email verification is required

POST /auth/register          { name, email, phone, password, role: "tenant" | "owner" }
  → 201  { user, verification: { email, emailOtpRequired: true } }       no tokens yet
         a 6-digit code + link are emailed (valid 24 h)

POST /auth/verify-email-otp  { email, otp: "482913" }
  → 200  { user, accessToken, refreshToken, expiresIn: "15m" }

POST /auth/resend-email-otp  { email }        60 s cooldown · always { sent: true }
  • Password must be 8–128 characters and contain at least one letter and one digit. Phone must be a Bangladeshi mobile number (01[3-9]XXXXXXXX, +88 optional).
  • Outside production the register response includes devEmailOtp, so QA can finish signup without a mailbox.
  • Phone (SMS) OTP is built but switched off. /auth/verify and /auth/resend-otp are inactive.

Log in and keep the session alive

POST /auth/login    { email, password }
  → 200  { user, accessToken, refreshToken }
  → 401  INVALID_CREDENTIALS
  → 403  EMAIL_NOT_VERIFIED      a new code was emailed → open the OTP screen

POST /auth/refresh  { refreshToken }
  → 200  { user, accessToken, refreshToken }                    store both new tokens
  → 401  PASSWORD_CHANGED | REFRESH_TOKEN_INVALID | ACCOUNT_MISSING  → log out
  1. Send Authorization: Bearer <accessToken> on every request.
  2. On 401 TOKEN_EXPIRED, call /auth/refresh once, behind a lock so parallel requests share it. Then replay the original request.
  3. If the refresh fails, clear both tokens and go to login.
  4. Logout returns 204 and clears web cookies only. Delete the stored tokens on the device yourself.
  5. Changing or resetting the password revokes every refresh token on every device. POST /auth/password returns new tokens for the current device.
  6. GET /auth/me answers { user: null } with status 200 when signed out. It does not return 401.

Verification and reset emails link to https://ghorbd.com/verify-email?token=… and https://ghorbd.com/reset-password?token=…. To open them in the app, set up App Links and Universal Links for those paths, then call POST /auth/verify-email or POST /auth/reset with the token.

Conventions & errors

{ "data": { … } }                                                       one item
{ "data": [ … ], "meta": { "page", "perPage", "total", "totalPages" } }  a list
{ "error": { "code": "VALIDATION_ERROR", "message": "…",
             "details": [ { "path": "title", "message": "…" } ] } }      an error
  • Branch on error.code, never on message.
  • ids are 24-character hex strings named id. Dates are ISO-8601 UTC; show them in Asia/Dhaka time.
  • Money is whole taka (pricePerMonth: 25000). Fields ending in Minor are poisha.
  • Phones are returned as +8801XXXXXXXXX.
  • A record you are not allowed to see returns 404, not 403.

Listing lifecycle

create(draft) ──► draft ──submit──► pending ──admin verify──► active
create()  (default)    ─────────► pending ──admin reject──► rejected ──submit──► pending
                         draft ◄──withdraw── pending
draft | pending | active ──archive──► archived ──submit──► pending
  • Owners cannot publish. Only an admin can move a listing to active. The transition response lists available actions; use it to decide which buttons to show.
  • land needs a land object and is always for sale. hotel needs hotel.totalRooms, is always for rent, and its price is per night.
  • The phone number is never in a listing payload. When hasContactPhone is true, reveal it with GET /listings/{id}/contact.
  • To share a listing, link to https://ghorbd.com + listing.path.
